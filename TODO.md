- [ ] (preview-emphasis-commonmark) Adopt CommonMark's full delimiter-stack algorithm for preview emphasis — **now also carries the stray-asterisk mispairing that (preview-bold-spans) could not fix.** `MarkdownInlineParser` commits to the **nearest** closer with no backtracking and no flanking rule, so a single stray `*` earlier in a block re-pairs every asterisk after it: `2 * 3 and **bold** here` renders "bold" as *italic* with a leftover `*`, and an odd/even count of strays decides whether the rest of the paragraph re-syncs. **(preview-bold-spans) planned to fix this with the opening clause alone — a `*`/`**` immediately followed by whitespace cannot open — on the claim that it changed no existing expected tree. That claim was disproved during implementation, twice (by hand against the shipped `parseNodes`, and by a probe implementing exactly the rule), and the proof is short:** index `*a **b** c*` as `*`(0) `a`(1) ` `(2) `*`(3) `*`(4) `b`(5) `*`(6) `*`(7) ` `(8) `c`(9) `*`(10); the third italic opens at index 7, whose next character is the **space** at index 8. The plan's own quoted expected tree gives it away — `.italic([.text(" c")])`, a body *beginning with a space*, is by definition an opener followed by whitespace. Under the rule that italic is rejected and the tail emits literally: `italic("a "), italic("b"), text("* c*")` instead of three italics. And this is structurally forced, not incidental — fixing `2 * 3 and **bold** here` **requires** rejecting `"* "`, and `*a **b** c*` contains `"* "`. So **no opener-only rule that fixes the report can leave `scripts/MarkdownRendererTests/main.swift:371` unchanged**, which is exactly the regression Rev 1's reviewer rejected. The fix therefore has to be the real algorithm, and it lands here. Two further findings from that work, both probe-confirmed, that this item must respect: (a) an opener-only rule leaves `**bold **` as bold, NOT literal — nothing rejects a closer *preceded* by whitespace, so the closer-side clause is unavoidable too; (b) a flatten-and-strip-`*` property fuzz **cannot** catch emphasis that swallows characters — `[.italic([]), .text(" bold"), .italic([])]` for `"** bold**"` satisfies it exactly (measured: that mutant scores 0 violations over 5000 inputs while two others score 1559 and 4570), so every asterisk-preservation case needs a hand-written expected tree.
