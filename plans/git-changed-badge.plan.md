# git-changed-badge

**Risk tier:** standard — the feature is read-only and purely cosmetic (a wrong or missing badge never touches file contents), and the blast radius is one new file plus additive hooks in `WorkspaceModel`/`SidebarView`/`ContentView`. The only genuinely error-prone areas — deadlock-safe subprocess I/O with a bounded timeout on a dedicated thread, the byte-level `-z` porcelain parse (renames, unicode, validated against desync), and off-main compute with burst coalescing — are contained in a single new type (`GitStatus`) plus one `WorkspaceModel` refresh path and empirically pinned below, so they warrant care but not a `hi` tier.

## Goal

When an opened top-level sidebar root is itself the root of a git repository (it directly contains `.git`), show a small right-aligned "(changed)" badge on each **file** row (never a directory) whose working-tree content differs from `HEAD` — modified, staged, untracked, or the new side of a rename. Status is computed off the main thread by shelling out to `git status --porcelain` (allowed: the app is unsandboxed, SPEC §2), cached per window as a `Set` of absolute file URLs, and refreshed on save, manual Refresh, app activation (the cheap HEAD-move signal), and — if it has shipped — external-change-watch events. Non-git roots and nested repos are never badged.

## Acceptance criteria

Fixtures: **RepoA** = a folder that is a git repo root, committed once, then dirtied to contain — one unchanged committed file, one modified tracked file, one staged-but-uncommitted file (`git add`), one untracked new file at the root, one untracked file inside a brand-new untracked subfolder, and one `git mv`-renamed file; plus a committed file with a non-ASCII name (e.g. `unicödé.txt`) that has been modified. **PlainB** = a folder with no `.git`. **Nested** = RepoA with a second `git init` in a subdirectory.

1. **Which files badge:** opening RepoA, the unchanged committed file shows **no** badge; the modified file, the staged file, the untracked root file, the untracked file inside the new subfolder (proves `-uall`), and the **new** path of the rename each show "(changed)".
2. **Directories never badge:** no directory row ever shows a badge, including a directory that contains changed files (e.g. the new untracked subfolder's own row).
3. **Non-git root:** every file under PlainB shows no badge (and no `git` process is spawned for it — repo-root detection short-circuits before any invocation).
4. **Both sidebar modes:** a changed file shows the badge in tree mode (empty filter) and, when the filter is non-empty, in the flat filtered list — the same file is badged identically in both (both render through the shared `FileRow`).
5. **Refresh triggers:**
   a. Edit a tracked file in FEdit and Cmd+S → that row gains "(changed)" with no manual action.
   b. From Terminal, `git commit -a` RepoA's changes, then switch back to FEdit → on app activation the badges clear. (This is the HEAD-move path — no polling, no `.git` watch.)
   c. Sidebar header context-menu **Refresh** recomputes and updates all badges.
   d. **Documented limitation (badge reconcile scope):** app **activation** and save recompute only the changed-*set* against the **already-present** tree rows — they reconcile *modification* badges on files that still have a row (e.g. 5b's commit clears them) but do **not** rescan the tree. So an externally **created** file has no row yet and therefore cannot badge on activation, and an externally **deleted** file leaves a stale row until the tree is rebuilt; picking up external **adds/deletes** requires a manual **Refresh** (the only trigger that rescans the tree via `refreshAll()`). Editing RepoA files from another tool *while FEdit stays the active app* likewise does not update badges until the next activation (for modifications) or Refresh (for adds/deletes) — there is no file-system watcher unless (external-change-watch) has shipped. Not a bug.
6. **Ignored files:** a file matched by `.gitignore` never shows a badge (`git status` without `--ignored` does not list it).
7. **Deleted-on-disk tracked file:** deleting a committed file on disk (git reports ` D`) does not crash; its row is gone from the tree anyway and other rows' badges stay correct.
8. **Non-ASCII name:** the modified `unicödé.txt` shows "(changed)" (verifies raw `-z` path → URL mapping). *Best-effort per assumption #5 (Unicode normalization).*
9. **Degrade gracefully:** with `git` unavailable, the path not a repo, a non-zero git exit, or very large output, the UI never blocks and never crashes — the window just shows no badges. (The git call is always off-main on a dedicated thread; every failure yields an empty set.) "Very large output" here is about the pipe-buffer **deadlock**, not memory: `readDataToEndOfFile()` buffers the whole listing in RAM, but that buffer is bounded by the D1 timeout (a runaway git is terminated at N s before it can stream unbounded output) — OOM is explicitly out of scope.
10. **Row layout:** on a selected (highlighted) badged row the badge stays legible; a long file name truncates (tail) *before* the badge is clipped — the badge is never truncated.
11. **Multi-window:** two windows open on RepoA each show consistent badges; a recompute in one window does not disturb the other's selection/scroll/open-file state.
12. **Subprocess timeout / no thread leak:** point the recompute at a hung or pathologically slow git (simulate with a wrapper that sleeps, or an enormous un-ignored tree) — within the stated **N = 5 s** the watchdog `terminate()`s the process, the recompute yields an empty set (no badges), the UI never blocks, and no worker thread is left parked (the dedicated serial queue is free for the next trigger).
13. **`-z` parse survives a desync (the one automated test):** feed `GitStatus`'s parser the exact bytes `R  new\0orig\0M  other\0` (an `R` status followed by **two** spaces, rename **target first**, then NUL, then the bare origin `orig`, then NUL, then a normal `M  other`) and assert the resulting changed-set is **exactly** `{ new, other }` — the discarded rename-origin `orig`, and any field that fails status-field validation, never leak in. This pins both the rename two-field advance and the desync guard. *(This is the single unit-testable seam; all other criteria are manual.)*

## Tiers

### Tier 1 — `GitStatus`: repo-root detection, off-main git invocation, parse, URL mapping

*Files:* new `FEdit/Models/GitStatus.swift`.

A dependency-free, UI-free enum of static functions. Nothing calls it yet (the file builds unused).

- `static func isRepositoryRoot(_ root: URL) -> Bool` — `FileManager.default.fileExists(atPath: root.appendingPathComponent(".git").path)`. True whether `.git` is a directory (normal repo) or a file (worktree/submodule gitlink); we only need "this root is a repo root". Cheap `stat`, safe to call on the main actor.
- `nonisolated static func changedFileURLs(inRepositoryRoot root: URL) -> Set<URL>` — **synchronous and blocking; callers must invoke it off the main actor on a dedicated thread** (Tier 2 runs it on a dedicated serial `DispatchQueue`, **never** the Swift cooperative pool — see the timeout below). Returns absolute, `.standardizedFileURL`-normalized file URLs of every changed path under `root`, or an **empty set on any failure** (git missing, launch throws, non-zero exit, decode failure, **or the watchdog timeout below**). Never throws, never crashes.
  - **Invocation:** `Process` with `executableURL = URL(fileURLWithPath: "/usr/bin/git")`, `currentDirectoryURL = root`, `arguments = ["--no-optional-locks", "status", "--porcelain=v1", "-z", "-uall"]`. Rationale per flag: `--no-optional-locks` so a badge recompute never takes the index lock and fights a concurrent git; `--porcelain=v1` pins a stable machine format across git versions; `-z` emits NUL-terminated, **unquoted** paths (no `core.quotepath` handling, no `""`-escaping to undo — verified: spaces and UTF-8 come through raw); `-uall` expands untracked directories to individual files (default `-unormal` collapses a new dir to a single `newdir/` entry, which maps to no file row). One call covers modified + staged + untracked + renamed — preferred over separate `git diff --name-only HEAD` + untracked-listing calls. **Cost of `-uall` (recorded, T1):** it walks *every* untracked file, so an un-`.gitignore`d large tree (a stray `node_modules`) makes `git status` slow; kept anyway because individual untracked files must badge (criterion 1), and the watchdog timeout below caps the worst case at N s → the window degrades to no badges rather than a hang.
  - **Deadlock-safe read + timeout (N = 5 s):** attach a `Pipe` to `standardOutput`; set `standardError = FileHandle.nullDevice` (**mandatory** — an undrained stderr pipe can fill its ~64 KB buffer and block git while we block reading stdout, exactly in the degradation paths; a throwaway/unread pipe reintroduces that deadlock, so **do not use one**). `try process.run()` inside a `do/catch` (launch failure → `[]`). **Arm a watchdog:** on a separate GCD queue (e.g. `DispatchQueue.global().asyncAfter(deadline: .now() + 5)` or a one-shot `DispatchSource` timer — never the cooperative pool), if the process is still running, call `process.terminate()` and set a lock-guarded `timedOut` flag. Read `pipe.fileHandleForReading.readDataToEndOfFile()` **before** `process.waitUntilExit()` — it returns when git closes stdout, i.e. on normal exit **or** when the watchdog terminates git (terminating closes the pipe, which is what makes the otherwise-uncancellable blocking read return, so a hung git cannot park the dedicated thread past N s). Draining first also avoids the 64 KB pipe-buffer deadlock a large `-uall` listing would otherwise hit. After `waitUntilExit()`, **cancel the watchdog timer**. If `timedOut` is set, or `terminationStatus != 0` (covers termination-by-signal, "not a repo", CLT stub without tools, etc.), return `[]`; only a clean `terminationStatus == 0` proceeds to parse.
  - **Parse (`-z` porcelain v1, empirically pinned):** the payload is a run of NUL-terminated fields. Iterate fields left-to-right with an index (not a naive per-field map — renames span two fields):
    - A **primary** field is `XY<space>PATH`: two status chars, one space at offset 2, then the path bytes. Fields shorter than 4 bytes are skipped (defensive). **Validate every primary field before trusting it (guards `-z` desync):** require `byte[2] == 0x20` (space) **and** each of `byte[0]`/`byte[1]` to be in the porcelain v1 XY alphabet `{ ' ', 'M', 'T', 'A', 'D', 'R', 'C', 'U', '?' }` (`'!'` never appears — we do not pass `--ignored`). A field that fails validation is **skipped and logged**, not parsed as a path — so if the rename two-field advance ever mis-steps, the damage is "miss one entry", never "misparse the rest of the stream". A bare rename-origin like `orig.txt` is ≥4 bytes and would pass the length guard, so length alone is insufficient — the alphabet/space check is what catches a desync (criterion 13).
    - If either status char is `R` or `C` (rename/copy), the record spans **two** fields — the primary field's `PATH` is the **new/current** path (this run's actual layout: `R  <newpath>\0<origpath>\0`, new first), and the **next** field is the original path, which is consumed and **discarded** (the old path no longer exists on disk, so it would match no row anyway). Not consuming it would misread the orig path as a bogus status record. The consumed origin field is taken **raw** — it is a path, not a status field, so it is *not* run through the primary-field validation above; the index simply advances past it. This single advance is the one spot a desync could originate, which is exactly why the *next* primary field is validated before use.
    - Decode each kept `PATH` from its raw bytes as UTF-8 (`String(decoding: bytes, as: UTF8.self)`), then map to a URL (below). A trailing empty field after the final NUL is ignored.
    - `!!` (ignored) never appears — we do not pass `--ignored`.
  - **Path mapping:** each kept root-relative POSIX path `P` → build the absolute URL by splitting `P` on `"/"` and `appendingPathComponent` each non-empty segment onto `root`, then `.standardizedFileURL`. (Segment-by-segment avoids any ambiguity in how `appendingPathComponent` treats an embedded `/`.) Because `FileNode` builds its node URLs the same way — `contentsOfDirectory` entries off the standardized root, each `.standardizedFileURL` — the mapped URL is byte-identical to the row's `node.url` and set-membership matches. **Do not** `resolvingSymlinksInPath` (FileNode does not; resolving would desync `/tmp` vs `/private/tmp`).

*Buildable/revertible:* the file compiles standalone; removing it reverts cleanly. No behavior change yet.

### Tier 2 — `WorkspaceModel`: cached changed-set + coalesced off-main refresh + internal triggers

*Files:* `FEdit/Models/WorkspaceModel.swift` (modify).

- `@Published private(set) var changedFileURLs: Set<URL> = []` — the per-window cache read by rows. A single flattened union across **all** repo-root roots in this window; membership is O(1). Non-git roots contribute nothing, so a row under a non-git root is simply never present (no per-row repo check needed).
- `private let gitQueue = DispatchQueue(label: "com.fedit.git-status")` — a **dedicated serial** GCD queue; the *only* place the blocking `Process` runs. Serial ⇒ at most **one** git job executes at a time (this alone bounds the app to a single live git process per window). It is **not** the Swift cooperative pool, so a blocking `readDataToEndOfFile()` never occupies a cooperative worker thread (see D1 timeout).
- **Burst coalescing without cancellation:** two `@MainActor` flags, `private var isRecomputing = false` and `private var recomputeAgain = false`. We deliberately do **not** rely on `Task.cancel()` to coalesce — a `cancel()` cannot stop an already-launched git `Process`, so the old "single in-flight `Task`" story was false the moment a compute outlived the debounce (a superseding trigger would spawn a *second* real git). Instead: while a recompute is in flight, further triggers set the one `recomputeAgain` flag, and the in-flight job re-runs **exactly once** when it finishes if that flag is set.
- `func scheduleGitRefresh()` — the one public trigger entry point (every caller funnels here), on the main actor:
  1. Compute `let repoRoots = roots.map(\.url).filter(GitStatus.isRepositoryRoot)`. If empty, set `changedFileURLs = []`, clear `recomputeAgain`, return (a window with no git roots clears cheaply — no job spawned).
  2. If `isRecomputing`, set `recomputeAgain = true` and return (collapse this trigger into the running job's single pending re-run).
  3. Else set `isRecomputing = true` and launch `Task { [weak self] in … }`. Inside: `try? await Task.sleep(for: .milliseconds(200))` (debounce/coalesce a burst — matters mainly for an (external-change-watch) event storm); then hop to the dedicated queue and back via a continuation — `let result = await withCheckedContinuation { cont in gitQueue.async { var u = Set<URL>(); for r in repoRoots { u.formUnion(GitStatus.changedFileURLs(inRepositoryRoot: r)) }; cont.resume(returning: u) } }` (the blocking `Process` work thus runs on the dedicated thread, off the cooperative pool). Back on the main actor (the class is `@MainActor`): assign `self.changedFileURLs = result`, set `isRecomputing = false`, and **if `recomputeAgain`** clear it and call `scheduleGitRefresh()` once more (which recomputes `repoRoots` fresh, so a roots change mid-flight is honored). `repoRoots` (array of `URL`) is `Sendable`; `GitStatus` is a nonisolated pure function — no data-race surface. Capture `gitQueue` strongly in the continuation so a deallocated window can never strand an unresumed continuation.
- **Internal triggers** (all call `scheduleGitRefresh()`):
  - `saveOpenFile()` — on the **success** branch, after `openFile = file` (a save changes working-tree vs HEAD).
  - `refreshAll()` — after rescanning (manual Refresh; also the user's explicit "pick up whatever changed" including HEAD moves and external edits).
  - `addFolders(_:)` — after appending new roots (so a freshly added git root badges without waiting for activation).
- **HEAD-move detection (decision):** no dedicated `.git/HEAD` watch and **no polling timer**. `git status --porcelain` already reflects the current `HEAD` on every run, so any recompute trigger inherently picks up a HEAD move — we only need a trigger that fires when the user is likely to have moved it. The realistic HEAD-move path is "user switched to Terminal, ran commit/checkout/reset, switched back", which is exactly app **activation** — wired in Tier 3 from `ContentView`. A per-window "became key" watch was rejected: it fires on intra-app window switches (which never change git state) yet still misses nothing app-activation catches.

*Buildable/revertible:* the set recomputes on save/refresh/add but nothing renders it yet. Reverting drops the property and hooks; no visible change. Note (T6): built **alone**, this tier still spawns real `git` processes on save/refresh/add (it wires `scheduleGitRefresh()` into those paths), but with no row rendering the set yet it is not *observably* testable until Tier 3 — verify the two together.

### Tier 3 — `FileRow` badge (tree + flat list) + activation trigger

*Files:* `FEdit/Views/SidebarView.swift` (modify), `FEdit/Views/ContentView.swift` (modify).

- **`FileRow`** (`SidebarView.swift`): in the **file** branch only (the `else` of `node.isDirectory`), append the badge to the trailing edge of the existing `HStack`. Give the name `.lineLimit(1)` + `.truncationMode(.tail)`, then a `Spacer(minLength: 6)`, then — when changed — `Text("(changed)")` at `.font(.system(size: 11))`, `.lineLimit(1)`, `.fixedSize()` (so the name yields first and the badge is never clipped, criterion 10). Foreground: match the label's treatment — the selected-row text color when `isSelected`, otherwise `.secondary`. Add a computed `private var isChanged: Bool { !node.isDirectory && workspace.changedFileURLs.contains(node.url) }`. The directory branch is untouched (criterion 2). Because both the `OutlineGroup` tree and `flatRows(for:query:)` render through this same `FileRow`, the flat filtered list gets the badge for free (criterion 4).
- **Activation trigger** (`ContentView.swift`): add `.onReceive(NotificationCenter.default.publisher(for: NSApplication.didBecomeActiveNotification)) { _ in workspace.scheduleGitRefresh() }`. Each window's `ContentView` subscribes, so each recomputes its own roots on activation (criterion 5b). Also call `workspace.scheduleGitRefresh()` once from the existing `.onAppear` (after `restore`), so badges appear on first launch without waiting for a deactivate/reactivate cycle. (`didBecomeActive` fires app-level on inactive→active transitions only — infrequent, and each fire coalesces through the Tier 2 debounce.)
  - **Reconcile scope (D4):** activation recomputes only the changed-*set* against the tree that already exists; it does **not** rescan the tree. So it reconciles *modification* badges on present rows (criterion 5b's post-commit clear works — those files still have rows) but cannot badge an externally-*created* file (no row yet) nor clear an externally-*deleted* file's stale row; those need a manual **Refresh** (`refreshAll()`, the only tree-rescan trigger). This limitation is stated in criterion 5d and deliberately **not** fixed — making activation rescan the tree isn't worth the cost.
  - **Cost with N windows (T2):** `didBecomeActiveNotification` is *app*-level, so on activation all N open windows' `ContentView`s fire → up to N git jobs (one per window). Coalesced per-window (Tier 2), **not** across windows. Acceptable for a personal single-user tool; recorded, not mitigated.
- **(external-change-watch) optional hook — do NOT hard-depend:** if/when that item ships its file/tree-change handler, it should add exactly one more caller of `workspace.scheduleGitRefresh()`. This plan neither imports nor references it; the feature is fully live on save + Refresh + activation alone, and merely gains sub-second liveness when the watcher exists.

*Buildable/revertible:* badges render and refresh. Reverting this tier removes the badge and the activation trigger, leaving Tier 2's machinery inert and harmless.

## Interface between tiers

- **Tier 1 → 2:** `GitStatus.isRepositoryRoot(_ root: URL) -> Bool`; `nonisolated GitStatus.changedFileURLs(inRepositoryRoot root: URL) -> Set<URL>` (synchronous, safe to call off-main, `[]` on every failure).
- **Tier 2 → 3:** `@Published private(set) var changedFileURLs: Set<URL>`; `func scheduleGitRefresh()`.
- **Tier 3** consumes both and adds no model API.

## Load-bearing assumptions

1. **(folder-sidebar) shipped** (verified): `WorkspaceModel` is a per-window `@MainActor ObservableObject` with `@Published private(set) var roots: [FileNode]`, `addFolders(_:)`, `refreshAll()`; `FileRow` is the single row view shared by the `OutlineGroup` tree and the flat filtered list; `ContentView` owns the `@StateObject` workspace and is per-scene.
2. **(open-save) shipped** (verified): `saveOpenFile() -> Bool` exists with a distinct success branch to hook.
3. `/usr/bin/git` exists and is a working git on the target machine (a developer's Mac — the project itself lives in a git repo). If git is absent or `/usr/bin/git` is the Command-Line-Tools stub without tools installed, the invocation throws or exits non-zero and degrades to no badges. Accepted edge: on a pristine machine the stub can surface the OS "install command-line developer tools" dialog on first invocation — low probability for this tool's audience, not mitigated in v1.
4. `git status --porcelain=v1 -z -uall` output layout, empirically pinned against git 2.55: primary field `XY<space>PATH`; a rename/copy (`R`/`C` in either status position) spans two NUL fields with the **new** path first and the original second; `-z` paths are raw/unquoted (no `core.quotepath`); `-uall` lists untracked files individually. `--porcelain=v1` freezes this format across versions.
5. A changed file's git-reported path bytes map to the same URL as `FileNode`'s `contentsOfDirectory`-derived node URL after `.standardizedFileURL`. Unicode normalization (NFC vs NFD) is assumed to agree in practice; a name with combining characters that git and the filesystem normalize differently is a known minor risk (criterion 8 is best-effort), affecting only whether that one file badges — never correctness elsewhere.
6. `WorkspaceModel` is `@MainActor`; the blocking `Process` runs on a **dedicated serial `DispatchQueue`** (not `Task.detached`/the cooperative pool); `standardError = FileHandle.nullDevice`; a **5 s watchdog** `terminate()`s a hung git; the pipe is drained with `readDataToEndOfFile()` before `waitUntilExit()` (deadlock-safe). Being unsandboxed (SPEC §2), launching `/usr/bin/git` needs no entitlement or security-scoped access.

## Out of scope

- **Nested git repos:** only the top-level opened root is treated as the repo root (via its direct `.git`). A repo nested inside a root is not separately detected; git run at the top root reports the nested repo per git's own rules (typically a single embedded-repo entry), and files inside it are not individually badged. Stated, not fixed.
- **Directories are never badged** (criterion 2) — even when they contain changed files.
- **No change-type distinction:** modified, staged, untracked, and rename-new all render the one uniform "(changed)" badge; no color/letter coding, no per-file diff.
- **Ignored files** are not badged (no `--ignored`) — desired.
- **A file-system watcher for liveness** belongs to (external-change-watch); without it, refresh is save + manual Refresh + app activation. This item adds no watcher and no timer.
- Branch name, ahead/behind counts, staged-vs-unstaged split, stash, submodule status, or any git UI beyond the sidebar file-row badge.
- Submodules as first-class (their gitlink may appear in the parent's status; not specially handled).

## Auto-resolved (plan review)

Findings from adversarial plan review, folded in above:

**Defects fixed**

1. *(High)* No subprocess timeout, and the blocking `readDataToEndOfFile()` was uncancellable — `Task.detached` isn't cancelled by cancelling the outer task and it occupies a cooperative-pool thread. Tier 1 now runs the `Process` on a **dedicated serial `DispatchQueue`** (Tier 2's `gitQueue`, never the cooperative pool) and arms a **5 s watchdog** that calls `process.terminate()`; terminating git closes stdout, which is what unblocks the otherwise-uncancellable read. On timeout the recompute returns an empty set (no badges) and never crashes. New **criterion 12** asserts a hung/slow git degrades to no-badges within N s with no parked thread; assumption #6 updated.
2. *(Medium)* The "single in-flight recompute" coalescing was false once a compute outlived the 200 ms debounce (`cancel()` can't stop the detached git, so a superseding trigger spawned a *second* real git). Tier 2 dropped the `Task`-cancellation story: the dedicated **serial** queue guarantees one git job at a time, and two main-actor flags (`isRecomputing` / `recomputeAgain`) collapse every trigger during a run into **one** pending re-run. The "single in-flight" wording is removed.
3. *(Medium)* The stderr guidance "throwaway pipe OR `/dev/null`" reintroduced the two-pipe deadlock (an undrained ~64 KB stderr pipe can block git while we block on stdout — exactly in the degradation paths). Tier 1 now **mandates** `standardError = FileHandle.nullDevice`; the throwaway-pipe option is deleted.
4. *(Medium)* Activation refreshes the changed-*set* but not the *tree* (`refreshAll()` alone rebuilds `roots`), so an externally-created file can't badge (no row) and an externally-deleted file leaves a stale row. Tier 3's activation bullet and **criterion 5d** now state explicitly that activation/save reconcile *modification* badges on already-present rows only; external adds/deletes require a manual **Refresh** (the sole tree-rescan trigger). Activation is deliberately **not** made to rescan the tree.
5. *(Medium)* The `-z` rename parse rested on one unvalidated index-advance; a bare origin path (`orig.txt`) is ≥4 bytes so the length guard passes and a desync would silently misparse the tail. Tier 1 now **validates every primary field** (`byte[2]` is space, and `byte[0]`/`byte[1]` are in the porcelain XY alphabet), skipping+logging failures so a desync costs at most one missed entry. New **criterion 13** is the item's one automated test: feeding `R  new\0orig\0M  other\0` must map **exactly** `{ new, other }`.

**Tensions recorded**

6. *(Medium, T1)* `-uall` walks every untracked file, so an un-`.gitignore`d large tree (a stray `node_modules`) slows `git status`. Kept for correctness (individual untracked files must badge); the D1 timeout caps the worst case. Recorded in Tier 1's `-uall` rationale.
7. *(Low, T2)* `NSApplication.didBecomeActiveNotification` is app-level, so N open windows fire N git jobs per activation — coalesced per-window, not across windows. Acceptable for a personal tool; recorded in Tier 3's activation bullet.
8. *(Low, T3)* SPEC §12 lists "git integration" as a v1 non-goal, yet this feature ships one. The SPEC work is now **in scope for this item**: the implementer adds the §5.6 "File status (git)" section **and** narrows §12 to sanction this one read-only badge. The former "note only — do NOT edit SPEC" heading is replaced by the "SPEC changes (part of this item)" section above.
9. *(Low, T4)* On a machine where `/usr/bin/git` is the Command-Line-Tools stub, an off-main invocation can surface the OS "install developer tools" dialog per trigger. Low-probability for this audience; recorded (assumption #3), not mitigated.
10. *(Low, T5)* `readDataToEndOfFile()` buffers all output in memory; criterion 9's "never crashes on very large output" is about the pipe-buffer **deadlock**, not OOM — the buffer is bounded by the D1 timeout. Criterion 9 clarified.
11. *(Low, T6)* Built alone, Tier 2 still spawns real git processes (it wires `scheduleGitRefresh()` into save/refresh/add) but isn't observably testable without Tier 3's rendering — recorded in Tier 2's buildable/revertible note.
