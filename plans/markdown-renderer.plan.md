# markdown-renderer

**Risk tier:** hi — two hand-written parsers (block + inline) with precedence rules, delimiter matching, and a strict anchor-ordering invariant that a downstream binary-search-style lookup depends on; blast radius is narrow (one new source file plus one standalone harness script — no project-file or scheme changes anywhere) but the parsers are genuinely algorithm-heavy, which is what keeps the tier at hi.

## Goal

Implement `FEdit/Preview/MarkdownRenderer.swift`: a pure, UI-free function `String → (NSAttributedString, [MarkdownAnchor])` covering the SPEC §8.2 Markdown subset, styled from `Editor/Theme.swift`, and emitting one `(sourceLine, outputLocation)` anchor per block element with the ordering guarantees required by the (markdown-preview) scroll-sync lookup (SPEC §8.3). Unit-verifiable via a standalone `swiftc` assertion harness (`scripts/MarkdownRendererTests/main.swift`) following the repo convention established by (filter-query) — no XCTest target, no `project.pbxproj` edit. No view code, no NSTextView, no rendering side effects.

## Acceptance criteria — concrete and testable

All criteria are asserted by the harness `scripts/MarkdownRendererTests/main.swift`, compiled together with the renderer sources via `swiftc` (see Tier 1). "Line" means a 0-based index into `source` split on `\n` (a trailing `\r` is stripped from each line, so CRLF input parses identically; this convention is part of the interface — see Interface between tiers).

### Block constructs

1. **ATX headings** — a line matching `#{1,6}` at column 0 followed by at least one space/tab produces a heading block of that level; heading text is the remainder after the marker with ALL leading and trailing whitespace stripped (`"##   Title"` → `"Title"`); heading text is inline-parsed; the trailing newline of the source line does not leak into the heading text. `#unspaced` and `####### seven` are NOT headings (they parse as paragraph text). A bare-marker heading (`"# "`) is a legal heading with empty text — it emits zero characters (see criterion 16). Heading levels 1–6 get distinct, **strictly decreasing** font sizes (taken from `Theme.headingFont(level:)`), all bold.
2. **Paragraphs** — consecutive lines that match no other block construct merge into one paragraph, joined with a single space; a blank line (empty or whitespace-only) terminates the paragraph. Test: `"a\nb\n\nc"` yields exactly two paragraph blocks with texts `"a b"` and `"c"`.
3. **Unordered lists** — lines starting (column 0) with `-`, `*`, or `+` followed by at least one space are list items; each source item is its own block element rendered with a bullet (`•`) prefix and hanging indent. Consecutive items form a visually continuous list (reduced inter-item paragraph spacing) but still yield one anchor each.
4. **Ordered lists** — lines matching `^[0-9]+[.)]\s` are ordered items; the rendered prefix is the source number plus `.` (e.g. `3.`), same indent/anchor behavior as unordered items.
5. **Blockquotes** — consecutive lines starting with `>` (one optional following space stripped per line) merge into a single blockquote block whose text is the per-line contents **joined with `\n`** (multi-line quotes are preserved, not space-flattened); a bare `>` line contributes an empty line (renders as a blank quoted line). The inline parser treats embedded `\n` as ordinary plain-text characters. Concrete case: `"> a\n>\n> b"` → one blockquote block whose text is the three per-line contents `"a"`, `""`, `"b"` joined with `\n`, i.e. exactly `"a\n\nb"`. Content is inline-parsed, rendered indented and in `Theme.mutedText`. A blank line or non-`>` line ends the quote.
6. **Fenced code blocks** — a line starting with three-or-more backticks **at column 0 only** (an indented ``` line falls through to paragraph text) opens a fence (any info string after the backticks is ignored); all following lines are taken verbatim (no inline parsing, no block interpretation — `# not a heading` inside a fence stays literal) until a closing line whose content is three-or-more backticks only, or EOF (an unterminated fence renders its collected content and must not crash). An immediately closed fence (`` ```\n``` ``) is a legal empty code block emitting zero characters (see criterion 16). Rendered in `Theme.codeFont` on `Theme.codeBackground`; internal newlines preserved.
7. **Horizontal rules** — a line consisting solely of three or more `-` or three or more `*` (optionally with trailing whitespace, no mixing of characters) is a rule; rendered as a full-line gray rule glyph run. Precedence: the rule check runs before the list-item check, and `- item` / `* item` (marker + space + text) still parse as list items.
8. **Block precedence & termination** — classification order per line is: inside-fence state → fence open → blank → heading → horizontal rule → blockquote → list item → paragraph continuation. A list item, heading, rule, quote, or fence line terminates a preceding paragraph without requiring a blank line.

### Inline constructs (apply inside headings, paragraphs, list items, blockquotes — never inside code blocks or code spans)

9. **Code spans** — `` `code` `` renders in `Theme.codeFont` on `Theme.codeBackground`; content is literal (no bold/italic/link parsing inside; `` `**x**` `` shows the asterisks). Code spans are matched before any other inline construct. An empty code span (` `` `) is legal: `.code("")` emits nothing visible.
10. **Links** — `[title](url)` renders the title styled as a link (`Theme.link` color, underline) with the `.link` attribute set to a **Foundation `URL`**; the brackets/parens are consumed. The `InlineNode` stores the url as the raw source `String`, verbatim; the emitter attempts `URL(string:)` and sets `.link` **only on success** — an unparseable/garbage URL gets NO `.link` attribute and its title renders as plain body-styled text (no link color/underline), the garbage URL kept verbatim in the node. Cross-plan decision with (markdown-preview): NSTextView's default link handling works with `URL` attribute values, so no custom click handling is needed there. `[title]` without `(url)`, or an unclosed form, renders literally.
11. **Bold** — `**text**` renders bold; the delimiter pair must be matched or the `**` renders literally. Bold content is recursively inline-parsed, so `**bold *italic* code `x`**` nests correctly. Empty content (`****`) is legal: `.bold([])`/empty text emits nothing visible.
12. **Italic** — `*text*` renders italic; at a scan position starting with `**`, bold is tried before italic, so `**` is never consumed as two italic delimiters. Unmatched `*` renders literally. Italic content is recursively parsed for code spans and links (not for bold). Empty content (`**` already went to bold; e.g. a matched pair around nothing) emits nothing visible.
13. **Literality** — with no backslash-escape support (out of scope), any delimiter that fails to match emits itself as plain text; no input may crash the parser or drop characters (property: concatenated plain text of the inline parse of a delimiter-free string equals the input). Consecutive literal characters coalesce into a single `.text` node, so `Equatable` tree assertions are deterministic.

**Closer-selection rule (pins one answer for every ambiguous input):** at each scan position the parser tries code span → link → bold → italic; for the construct that opens, the closer is the **nearest matching closing delimiter after the opener, scanning left to right, with no backtracking** — if none exists, the opener emits as literal text and scanning resumes after it. The following adversarial cases are acceptance-test cases, each expected tree derived mechanically from this rule:

- `**a*b**` → `[.bold([.text("a*b")])]` — bold opener at 0–1; nearest `**` scanning from index 2 is at 5–6; body `a*b` recursively parses to a single text node (its lone `*` finds no closer → literal).
- `***x***` → `[.bold([.text("*x")]), .text("*")]` — bold opener at 0–1; scanning for `**` from index 2: 2–3 is `*x` (no), 4–5 is `**` (closer); body indices 2–3 = `*x` (inner `*` unmatched → literal); remaining index 6 `*` finds no closer → literal.
- `**a**b**` → `[.bold([.text("a")]), .text("b**")]` — closer at 3–4 gives bold("a"); then `b` is text; the final `**` opens but finds no closer → literal, coalesced with `b` into one text node.
- `*a **b** c*` → `[.italic([.text("a ")]), .italic([.text("b")]), .italic([.text(" c")])]` — italic opener at 0; nearest `*` from index 1 is the first `*` of `**` (index 3) → italic("a "); resume at index 4: `*` followed by `b` (not `**`) opens italic, closer at 6 → italic("b"); resume at 7: `*` opens italic, closer at 10 → italic(" c"). The rule deliberately does not try to make this "look right" — it pins ONE answer.

### Anchors and output invariants

14. **Coverage** — exactly one anchor per block element: per heading, per paragraph, per list item (not per list), per blockquote block, per fenced code block (anchored at the opening-fence source line), per horizontal rule. Blank lines and lines swallowed into a merged block produce no anchor of their own.
15. **sourceLine** — each anchor's `sourceLine` is the 0-based source line of the block's first line. The anchors array is **strictly ascending in `sourceLine`**.
16. **location** — each anchor's `location` is the UTF-16 offset (`NSAttributedString` location) of the block's first character in the output, in range `0...output.length`, and the array is **strictly ascending in `location`**. The strict ascent is guaranteed by the separator, NOT by block non-emptiness: `anchor[i+1].location ≥ anchor[i].location + emitted(block[i]) + 1` because a single `\n` separator follows every non-final block, **including empty ones** — an empty fence (`` ```\n``` ``) and a bare-marker heading (`"# "`) both emit zero characters, so "every block emits at least one character" is false and must never be relied on. Do not "optimize" the separator away for empty blocks; it is load-bearing for this invariant. Visual spacing is done via `NSParagraphStyle.paragraphSpacing`, never via padding blank lines. Explicit strict-ascent test: the two-empty-fences input `"```\n```\n```\n```"` (two consecutive empty code blocks) must still produce strictly ascending anchor locations. These two orderings make the §8.3 "greatest anchor with sourceLine ≤ firstVisibleLine" lookup well-defined.
17. **Edge inputs** — empty string → empty attributed string, empty anchors; whitespace-only input → no anchors; input without trailing newline, CRLF input, a single 10 000-character line, a document that is one giant unterminated fence, the two-empty-fences document of criterion 16, and a bare `"# "` heading all render without crashing; rendering is deterministic (same input → equal output string, attributes at probe points, and anchors).
18. **Purity** — `render` is a static function with no `@MainActor`/AppKit-view dependencies beyond `NSAttributedString`/`NSColor`/`NSFont`/`NSParagraphStyle`; calling it never touches shared mutable state (safe to call from a debounce queue later).

## Tiers

### Tier 1 — Block model + block parser + swiftc harness

Buildable/revertible unit: compiles, block-level harness cases green; deleting the source file and the `scripts/MarkdownRendererTests/` directory reverts it. No project-file or scheme change at any tier.

- **Create `FEdit/Preview/MarkdownRenderer.swift`** (GPL header per project boilerplate) containing, for now:
  - `struct MarkdownAnchor: Equatable { let sourceLine: Int; let location: Int }` (public API surface, used from Tier 3 on).
  - `enum MarkdownBlock: Equatable` — internal block model: `.heading(level: Int, text: String, line: Int)`, `.paragraph(text: String, line: Int)`, `.listItem(marker: String, text: String, line: Int)` (marker is the rendered prefix, `•` or `"3."`), `.blockquote(text: String, line: Int)`, `.codeBlock(code: String, line: Int)`, `.rule(line: Int)`.
  - `enum MarkdownBlockParser { static func parse(_ source: String) -> [MarkdownBlock] }` — line splitter (split on `\n`, strip trailing `\r`), fence state machine, classification in the precedence order of criterion 8, paragraph/blockquote merging, list-item and heading/rule recognition per criteria 1–8. Pure `Foundation`-only code (no AppKit needed in this tier).
- **Create `scripts/MarkdownRendererTests/main.swift`** — a top-level assertion harness following the repo's established swiftc-harness convention (see `plans/filter-query.plan.md`): repo-root `scripts/` sits outside `FEdit/`, so the file-system-synchronized group never pulls it into the app target, and the file MUST be named `main.swift` — Swift only allows top-level statements in `main.swift` when compiling multiple files. Same shape as the filter-query harness: an `expect(_:_:)` helper printing `PASS`/`FAIL`, a failure count, `exit(1)` on any failure. Run command (documented in a comment at the top of the script):
  `swiftc FEdit/Preview/MarkdownRenderer.swift FEdit/Editor/Theme.swift scripts/MarkdownRendererTests/main.swift -o /tmp/mdtests && /tmp/mdtests`
  Multi-file `swiftc` compiles everything into one module, so internal types (`MarkdownBlockParser`, `MarkdownBlock`, later `InlineNode`) are directly testable — no `@testable`, no XCTest target, no scheme surgery, no `project.pbxproj` edit. `Theme.swift` imports AppKit, which plain `swiftc` handles fine on macOS. Tier 1 fills the harness with cases for criteria 1–8 and the block-level halves of 17 (empty, CRLF, unterminated fence, no trailing newline, empty fence, blockquote `\n`-joining); Tiers 2–3 extend this same file.

## Interface between tiers

- Tier 1 → Tier 3: `MarkdownBlockParser.parse(String) -> [MarkdownBlock]`; every case carries `line: Int` (0-based first source line) which becomes the anchor's `sourceLine` unchanged.
- Tier 2 → Tier 3: `MarkdownInlineParser.parse(String) -> [InlineNode]`; the emitter is the only consumer that maps nodes to attributes.
- Tier 3 → downstream (markdown-preview) item: `MarkdownRenderer.render(_:)` and `MarkdownAnchor`. **Contract exported to that item:** `sourceLine` is 0-based over `\n`-split lines (CRLF tolerated); `location` is a UTF-16 offset into `output`; both arrays' fields are strictly ascending, so "greatest anchor with `sourceLine ≤ editorFirstVisibleLine`" is a plain binary search. The editor's first-visible-line callback must use (or be converted to) the same 0-based convention. **Consumer warnings (exported):** (a) a trailing empty block (empty fence, bare `"# "` heading) yields an anchor with `location == output.length` — a zero-length position at end-of-storage; the preview's `boundingRect`-style lookup must tolerate a zero-length range at the end of the text storage. (b) `.link` attribute values are Foundation `URL`s and are present only when the source URL parses.

## Out of scope

- Tables, images, footnotes, HTML passthrough, setext headings, nested lists (beyond the single level rendered), per-language highlighting inside fenced blocks — SPEC §8.2 non-goals.
- Backslash escapes (`\*`), reference-style links, autolinks, hard line breaks (two-space), indented (4-space) code blocks, lazy list/quote continuation lines (a non-marker line after a list item starts a new paragraph).
- Any UI: `MarkdownPreviewView`, scroll sync, debounce, ContentView wiring — all (markdown-preview).
- Modifying `Editor/Theme.swift`, `SyntaxHighlighter.swift`, or any existing source; editor-side Markdown highlighting (§6.3) is unrelated to this renderer.
- Adding an XCTest target or any `project.pbxproj`/scheme modification — v1 verification is the swiftc harness; porting to XCTest happens only if a test target ships in some later item.
- Performance work beyond linear-time parsing (files are expected small per SPEC §6.3 rationale).
